# 온라인 멀티플레이 구조

## 권한 모델

클라이언트는 `throw`, `move`, `useAugment` 같은 행동 의도만 보낸다. `RoomManager`가 플레이어 신원, 현재 차례, 상호작용 담당자, 증강 선택 후보, 상태 순서 번호를 검사한 뒤 공통 `Game`/`AugmentEngine`을 실행한다. 윷 결과와 말 위치는 서버가 최종 결정한다.

각 명령에는 다음 값이 포함된다.

- `commandId`: 재전송된 동일 명령을 한 번만 처리하는 UUID
- `expectedSequence`: 오래된 화면에서 보낸 명령을 거부하는 상태 순서 번호
- `type`, `payload`: 서버가 허용 목록으로 해석하는 행동

클라이언트가 `모` 같은 윷 결과를 지정하면 거부한다. 개돼지 증강의 도/개 선택만 공통 엔진이 다시 검증한다. 알까기 목표값은 서버의 65로 고정되며 클라이언트가 명중 기준을 바꿀 수 없다.

## 방과 재접속

- 방 코드는 충돌을 검사한 무작위 6자리 숫자다.
- 플레이어별로 256비트 재접속 토큰을 발급하고 브라우저 `localStorage`에만 저장한다.
- 동일 플레이어가 새 기기/탭에서 토큰으로 접속하면 이전 소켓을 교체한다.
- 방장 연결이 끊기면 접속 중인 다음 플레이어에게 방장을 이전한다.
- JSON 저장소를 설정하면 서버 재시작 뒤 방, 게임, 명령 이력을 복원한다.
- 비밀번호는 scrypt + 무작위 salt 해시만 저장하며 로그와 개인화 상태에 포함하지 않는다.
- 방장 승인 대기자는 승인 전까지 플레이어/재접속 토큰을 발급받지 않는다.
- 방장은 대기실 참가자를 내보낼 수 있고 게임 시작 뒤 새 참가와 강퇴를 막는다.
- 빈 방, 종료 방, 장시간 비활성 방은 서로 독립적으로 TTL 정리된다.
- 종료 뒤 방장이 같은 참가자·설정으로 다시 플레이할 수 있다.

## 비공개 정보

서버는 플레이어마다 다른 상태 view를 만든다.

- 1·6·12라운드 후보는 본인의 세 장만 전송한다.
- 눈치싸움의 공동 후보는 서버에서 만들되 선택 완료 전 다른 사람의 선택은 보내지 않는다.
- 블러핑 실제 결과, 죄수의 딜레마 미완료 선택, 비공개 윷 결과를 상대 view에서 제거한다.
- 안개 밖 상대 말은 좌표와 경로를 제거한 `hiddenOnline` 상태로 전송한다.
- 상호작용 담당자가 아닌 플레이어에게는 선택 내용 대신 대기 상태만 전송한다.

## 87개 증강 연결

온라인 전용 규칙 사본을 만들지 않는다. 범용 57개와 전용 30개는 서버가 동일한 `AugmentEngine`을 호출한다. 수동 증강, 특수 말, 판 접기/회전, 포획·사망, 특수 승리·탈락, 부활과 공동 승리가 모두 같은 직렬화 상태를 사용한다. 여러 플레이어 선택은 `interaction:resolve`로 현재 담당자만 제출할 수 있다.

## 주요 이벤트

클라이언트 → 서버:

- `room:create`, `room:join`, `room:resume`, `room:leave`
- `room:settings`, `room:ready`, `room:start`, `room:rematch`
- `room:approve`, `room:kick`
- `game:command`

서버 → 클라이언트:

- `online:state`: 해당 플레이어용으로 필터링한 전체 최신 상태
- `online:connection`: 연결 상태
- `online:session-replaced`: 같은 토큰의 새 접속으로 기존 세션이 교체됨
- `room:approved`, `room:approval-denied`, `room:kicked`

## 입력 방어와 상태 검사

- 입장, 대기실 조작, 게임 명령에 서로 다른 고정 창 속도 제한을 적용한다.
- 명령 ID와 순서 번호로 중복/오래된 입력을 거부한다.
- payload 크기와 미니게임 숫자 범위를 제한한다.
- 명령 전후 게임 상태를 검사하고 실패한 명령은 해당 방 스냅샷만 롤백한다.
- 오류 응답은 예상된 코드만 공개하고 예기치 않은 예외의 내부 메시지는 숨긴다.
- `/health`, `/ready`, `/metrics`로 생존·무결성·전송 크기를 관찰한다.

## 로컬 실행

터미널 1:

```bash
pnpm dev:server
```

터미널 2:

```bash
pnpm dev --host 127.0.0.1 --port 4173
```

브라우저의 서로 다른 프로필 또는 기기에서 `http://127.0.0.1:4173`을 열고 온라인 플레이를 선택한다. 다른 기기에서는 서버/프런트 포트가 방화벽에서 허용되어야 하며 localhost 대신 개발 PC의 LAN 주소를 사용한다.
